# Ham & Ham — موقع المطعم والحفظ السحابي (مجاني)

نسخة جاهزة للنشر من موقع Ham & Ham: **53 منتجًا أصليًا مع الصور**، سلة طلبات وواتساب، بحث وتصنيفات، لوحة إدارة بحساب **مدير واحد**، وحفظ سحابي مؤكد قبل ظهور رسالة النجاح. أزيل رمز البرغر الذي كان يظهر بدل صور الوجبات، وأُوقفت حركة تكبير صور الوجبات.

> **مهم:** الملفات تعمل بوضع المعاينة فقط قبل إعداد Supabase. لا يمكنك تسجيل الدخول أو حفظ تعديل دائم قبل تنفيذ الخطوات أدناه. لا يمكن لأي ملف HTML بمفرده توفير تسجيل دخول آمن وحفظ بين الأجهزة.

## 1. أنشئ مشروع Supabase مجانًا

1. افتح https://supabase.com/dashboard وأنشئ حسابًا ومشروعًا جديدًا على **Free** (دون الترقية إلى Pro).
2. من **SQL Editor** افتح ملف `backend/01_schema.sql`، انسخ النص كاملًا ونفّذه Run. سيُنشئ قاعدة البيانات وقواعد الأمان ومساحة صور عامة القراءة.
3. من **Authentication → Users → Add user** أنشئ **حسابًا واحدًا لك فقط**، ببريد إلكتروني حقيقي وكلمة مرور قوية، وفَعِّل تأكيد البريد للحساب إذا طلبت الواجهة ذلك. **لا تضع كلمة المرور في أي ملف**.
4. انسخ **User ID / UID** للحساب الذي أنشأته. افتح `backend/02_set_admin.sql` واستبدل `00000000-0000-0000-0000-000000000000` بالـ UID الحقيقي، ثم نفّذ SQL. هذا يربط صلاحية الإدارة بحسابك وحدك.
5. من إعدادات **Authentication → Providers → Email** عطّل التسجيل العام للمستخدمين الجدد (**Allow new users to sign up**) إن توفر الخيار. الموقع أصلًا لا يحتوي زر تسجيل؛ لكن تعطيل التسجيل إجراء إضافي.

**تنبيه أمني:** إذا أضفت أي مستخدم Auth آخر إلى Supabase لاحقًا فلن يستطيع تعديل البيانات دون إدراجه في جدول `shop_admins`. احتفظ بصف واحد فقط في هذا الجدول.

## 2. اربط المشروع بالموقع

1. من مشروع Supabase افتح **Project Settings / Connect / API** (قد يختلف موضع القسم حسب تحديث الواجهة).
2. انسخ **Project URL** والمفتاح **Publishable key** أو **anon public key**، وليس `service_role` أو مفتاح `secret`.
3. افتح `site/config.js` وأدخل:

```javascript
window.HAMHAM_CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLISHABLE_OR_ANON_KEY",
  ADMIN_USERNAME: "hamham",
  ADMIN_EMAIL: "your-admin-email@example.com"
};
```

- تستطيع تغيير `ADMIN_USERNAME` إلى اسم تختاره. سيكون اسم الدخول الظاهر داخل الموقع، ومقترنًا بحساب البريد الموجود في Supabase.
- كلمة المرور تُكتب فقط في شاشة الدخول، وتتحقق منها Supabase؛ **لا تخزنها في GitHub**.
- عنوان المشروع والمفتاح العام والبريد المخصص للربط ظاهرة ضمن ملفات الواجهة، وهذا طبيعي. **قواعد RLS هي التي تمنع تعديلات الزوار**.
- للحماية الإضافية، تستطيع استخدام بريد مخصص للإدارة لا تستعمله للعموم.

## 3. جرّب الموقع محليًا

من مجلد المشروع شغّل:

```bash
python -m http.server 8000 --directory site
```

ثم افتح `http://localhost:8000`. عند الاتصال يجب أن تظهر علامة **متصل بالسحابة** أعلى الموقع. اضغط ⚙️ وسجّل الدخول باسم المستخدم وكلمة مرور Supabase. في المرة الأولى اضغط **«تهيئة المنيو في السحابة»** لرفع منتجات البداية الـ53 إلى قاعدة البيانات. يجب أن ترى بعدها تأكيد نجاح الحفظ من الخادم.

جرّب تغيير سعر وجبة واحدة، اضغط «حفظ المنتج»، ثم افتح الموقع على جهاز آخر أو نافذة خاصة: يظهر السعر الجديد. **الحفظ فوري في الخادم**؛ يجلب الزائر أحدث الأسعار عند فتح الموقع، والصفحات المفتوحة تحدّث نفسها عند العودة إليها أو كل دقيقة تقريبًا.

## 4. انشره مجانًا باستخدام GitHub وCloudflare Pages

1. أنشئ مستودع GitHub جديدًا (Public أو Private) وارفع محتويات مجلد `hamham-cloud` كاملة، مع مجلد `site` وملفات SQL وREADME.
2. افتح https://dash.cloudflare.com/ واختر **Workers & Pages → Create → Pages → Connect to Git** ثم اربط حساب GitHub والمستودع.
3. اضبط **Production branch** على `main`، و **Build command** على `exit 0`، و **Build output directory** على **`site`** بالضبط.
4. اضغط Deploy. ستحصل على عنوان مجاني ينتهي بـ `.pages.dev`.
5. للزيارات العادية لا حاجة إلى GitHub أو تسجيل دخول. بعد تعديل وجبة من لوحة الإدارة، التغييرات تُحفظ في Supabase وتظهر دون تعديل ملفات GitHub أو إعادة نشر.

> نستخدم Cloudflare Pages لتقديم الموقع، وGitHub لحفظ الكود؛ GitHub Pages ليس خيارًا مناسبًا لاستضافة موقع تجاري للطلبات وفق قيود الاستخدام المنشورة.

## 5. الاستخدام اليومي

- **الدخول:** ⚙️ → اسم المستخدم المحدد في `config.js` → كلمة مرور حساب Supabase.
- **حفظ التعديلات:** تحرير وجبة/إضافة وجبة → «حفظ». لا تظهر رسالة «تم حفظ التغييرات» إلا بعد تأكيد تحديث الصف من Supabase.
- **فشل الإنترنت:** تظهر رسالة خطأ ولا يُغلق نموذج التحرير، فتستطيع إعادة المحاولة. يتم تعطيل إتمام الطلب إذا لم تُحمَّل الأسعار من السحابة.
- **الإعدادات:** عدّل الحقول ثم اضغط **«حفظ الإعدادات في السحابة»**. تغيير الحقول وحده **لا يحفظها**؛ سترى تنبيهًا «لديك إعدادات غير محفوظة».
- **الخروج:** زر تسجيل الخروج الآمن؛ تبقى التعديلات السابقة في السحابة، وتختفي أدوات التعديل.
- **صور جديدة:** تُضغط تلقائيًا إلى WebP ثم تُرفع إلى Supabase Storage؛ الصور الأصلية تأتي مباشرةً من ملفات المشروع ولا تستهلك Supabase Storage.
- **حفظ احتياطي:** تنزيل ملف JSON من لوحة الإدارة؛ ويمكن استيراده عند الحاجة (مع إعادة رفع الصور المضمّنة لنسخة HTML القديمة).
- **أجهزة متعددة:** إذا حصل تعارض بين تعديلين في وقت واحد، يمنع النظام الحفظ فوق تعديل حديث دون تنبيه؛ حدّث البيانات ثم أعد المحاولة.

## 6. هل الخدمة مجانية 100%؟

للبداية، يمكن استخدام خطط Free دون دفع أو نطاق مدفوع، **ضمن حدود الاستخدام المجاني الحالية**. Supabase Free يفرض حدودًا على مساحة البيانات وتخزين الصور والاتصالات، وقد يوقف المشاريع غير النشطة لفترة. لذلك:

- لا تختَر خطة Pro ولا تفعّل إضافات مدفوعة؛ راقب حدود الاستخدام من لوحة Supabase.
- استفد من عنوان Cloudflare المجاني `*.pages.dev` بدل شراء دومين.
- تنزيل نسخ احتياطية JSON بانتظام مفيد خاصة مع خطط Free.
- **لا يوجد ضمان بأن الخدمة ستبقى مجانية بلا قيود إلى الأبد**؛ السياسات قد تتغير.

## الملفات

```text
hamham-cloud/
├── site/                 # فقط هذا المجلد يُنشر كواجهة عامة
│   ├── index.html        # واجهة عربية RTL
│   ├── app.js            # إدارة، سلة، مصادقة، حفظ وتصدير
│   ├── starter-menu.js   # أسماء وأسعار الـ53 منتجًا
│   ├── config.js         # بيانات الربط العامة، من دون كلمة المرور
│   ├── _headers          # رؤوس أمان Cloudflare
│   └── assets/           # الشعار والصور الأصلية
├── backend/
│   ├── 01_schema.sql     # يُنفَّذ أولاً في Supabase
│   └── 02_set_admin.sql  # ضع UID الحقيقي ثم نفّذه
└── README_AR.md
```

**لا ترفع** كلمة المرور، مفاتيح `secret` أو `service_role`، أو بيانات الحساب الشخصية الحساسة إلى GitHub.
